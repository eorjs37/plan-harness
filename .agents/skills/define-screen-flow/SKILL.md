# Figma에 화면정의서와 프로세스 흐름 작성하기

저장소 루트에서 Codex를 열고 입력창에 다음과 같이 입력한다.

```text
$define-screen-flow raidio-biz winter-new-channel-popup https://www.figma.com/design/FILE_KEY/Raidio-Biz?node-id=123-456
```

1. 프로젝트명, 기능 폴더명, Figma Design URL을 차례로 받는다. 첫 두 값은 영문 소문자와 숫자로 이루어진 단어를 하이픈으로 연결한 폴더명이다. URL은 Figma Design의 파일, 페이지 또는 프레임 링크를 받는다. 값이 빠졌거나 잘못된 경우 호출 예시를 안내하고 중단한다.
2. `projects/<프로젝트>/project.md`와 `projects/<프로젝트>/features/<기능>/`의 `requirements.md`, `tasks.md`를 읽는다. 요구사항에서 화면과 정책을, 과제에서 확인할 동작을 가져온다. 필수 자료가 없으면 필요한 파일을 안내하고 중단한다. 미확정 내용은 ‘확인 필요’로 표시한다.
3. 공식 Figma MCP와 Figma 작성 지침을 사용한다. URL에서 파일 키와 노드 ID가 있으면 해당 ID를 확인한다. 대상 파일의 세션을 열어 기준 페이지 또는 프레임과 편집 권한을 확인한다. 파일 링크만 있으면 문서에 명시된 화면을 찾고, 대상이 모호하면 기준 프레임 링크를 요청한다.
4. 대상 파일에 기능 이름을 붙인 별도 섹션을 만들거나 기존 기획 섹션을 갱신한다. 기준 화면과 연결해 아래 내용을 작성한다. 화면을 설명할 때는 기존 프레임을 참조하거나 필요한 부분만 단순한 와이어프레임으로 표시한다.
   - **화면정의서** — 화면 이름, 주요 영역과 요소, 표시 조건, 누르면 일어나는 동작, 정책에 따라 달라지는 상태를 적는다.
   - **프로세스 흐름** — 시작 화면, 사용자 행동, 화면 전환 또는 같은 화면 안에서의 이동, 결과를 순서대로 연결한다. 요구사항에 명시된 분기와 예외를 표시한다.
5. 두 산출물이 요구사항과 과제의 완료 확인 방법을 반영하는지 확인한다. 결과 섹션 링크와 남은 확인 사항을 알려준다.

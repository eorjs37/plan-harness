# 기능 요구사항 정의하기

저장소 루트에서 `$define-requirements raidio-biz winter-new-channel-popup`처럼 호출한다. 첫 번째 값은 프로젝트 폴더명이고 두 번째 값은 기능 폴더명이다.

1. 두 값이 영문 소문자와 숫자로 이루어진 단어를 하이픈으로 연결한 이름인지 확인한다. 값이 빠졌거나 형식이 맞지 않으면 호출 예시를 안내하고 중단한다.
2. `projects/<프로젝트>/project.md`와 `projects/<프로젝트>/features/<기능>/`의 `request.md`, `analysis.md`를 읽는다. 필요한 문서를 찾을 수 없거나 요청서에 답변이 없으면 작성에 필요한 내용을 안내한다. 분석서의 답변과 최신 요청서의 변경 사항을 확인한다. 두 문서의 내용이 달라 요구사항에 영향을 주면 확인할 사항으로 기록한다.
3. `templates/requirements.md`의 양식에 따라 목표와 범위, 사용자 흐름, 정책과 예외, 요구사항 확인 방법을 작성한다. 사용자 행동과 그때 나타나야 할 결과를 확인할 수 있게 적는다. 간단한 변경은 필요한 항목만 작성한다. 아직 확정되지 않은 화면 이동, 적용 조건 등은 **결정이 필요한 사항**에 확인 대상이나 방법과 함께 적는다.
4. 결과를 같은 기능 폴더의 `requirements.md`에 저장한다. 기존 문서가 있으면 먼저 읽고, 갱신 요청을 받은 경우 기존 결정의 근거와 관련 변경 기록을 보존하며 수정한다. 저장 경로와 다음 단계에 영향을 주는 미결 사항을 알려준다.
